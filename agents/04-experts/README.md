# Tier 04: Expert Agents

Expert agents bring cutting-edge specialization in AI/ML, LLM systems, and advanced technical domains. Use them for production AI systems, MLOps, and complex technical challenges.

## When to Use Expert Agents

Use these agents when you need to:
- **Design LLM/AI systems** with production requirements
- **Build ML pipelines** with proper MLOps practices
- **Create RAG systems** and AI-native applications
- **Optimize prompts** for accuracy and security
- **Deploy production ML** with monitoring and evaluation

## Available Agents

### [machine-learning-engineer](machine-learning-engineer.md)
ML/AI expert for PyTorch, TensorFlow, MLOps, model training, deployment, MLflow, Kubeflow, feature engineering, and production ML systems.

**Use when:** Machine learning projects, AI implementation, model deployment, MLOps pipelines.

### [llm-architect](llm-architect.md)
LLM system architect for designing production AI/ML systems including RAG pipelines, prompt engineering infrastructure, LLM orchestration, agent frameworks, and AI-native applications.

**Use when:** LLM integration, AI system design, RAG pipelines, production AI deployment.

### [prompt-engineer](prompt-engineer.md)
Prompt engineering specialist for designing, optimizing, and evaluating LLM prompts for production applications.

**Use when:** Prompt design, few-shot learning, chain-of-thought prompting, prompt optimization and security.

## Quick Selection Guide

| If you need to... | Use this agent |
|-------------------|----------------|
| Build ML models | **machine-learning-engineer** |
| Design LLM/RAG systems | **llm-architect** |
| Optimize prompts | **prompt-engineer** |
| Deploy ML to production | **machine-learning-engineer** |
| Create AI agents | **llm-architect** |
| Secure LLM applications | **prompt-engineer** |

## Common Combinations

**Production AI Application:**
1. `llm-architect` → System design for LLM app
2. `prompt-engineer` → Optimize prompts
3. `backend-architect` → API and infrastructure
4. `observability-engineer` → LLM monitoring

**ML Platform:**
1. `machine-learning-engineer` → ML pipeline design
2. `data-pipeline-engineer` → Feature engineering pipelines
3. `devops-automation-expert` → MLOps CI/CD
4. `observability-engineer` → Model monitoring

**RAG System:**
1. `llm-architect` → RAG architecture
2. `database-architect` → Vector store selection
3. `prompt-engineer` → Retrieval prompts
4. `backend-architect` → API layer

## Best Practices

- **Start with architecture**: Use `llm-architect` before implementation
- **Prompt early**: Involve `prompt-engineer` in design phase
- **MLOps first**: Build deployment pipeline before complex models
- **Monitor everything**: LLM systems need extensive observability
- **Security focus**: Prompt injection is a real threat
